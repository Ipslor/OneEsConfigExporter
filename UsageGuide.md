# Инструкция пользователя — Выгрузка конфигурации 1С v.2.5.2

## Быстрый старт

Утилита работает со списком баз. Одна строка и несколько строк обрабатываются одинаково, последовательно.

1. Распакуйте архив в доступную для записи папку и запустите OneCConfigExporter.exe.
2. Нажмите «Настройки», выберите платформу 1С и нажмите «Применить». Git и GitHub для простой выгрузки необязательны.
3. В группе «Информационная база» нажмите «Добавить».
4. Выберите зарегистрированную базу или задайте параметры вручную. Укажите отдельный каталог файлов и полный/инкрементальный режим. Заполните авторизацию при необходимости.
5. Для полной копии отключите общий фильтр размера: по умолчанию он включён с лимитом 30 МБ.
6. Отметьте нужные строки и нажмите «Выполнить».
7. Подтвердите вопрос «Начать выгрузку? Убедитесь, что конфигураторы всех баз будут доступны для запуска!».
8. Дождитесь результатов в строках списка. При ошибке прочитайте «Пояснение» и вкладку «Журнал».

## Список баз

«Копировать» создаёт новую запись из выбранной строки и открывает её редактирование. Можно выбрать инкрементальную копию: режим переключится на инкрементальный, новая строка будет отмечена, исходная — снята после сохранения копии. При отмене редактирования исходная строка не меняется. Обычная копия создаётся неотмеченной.

Так удобно хранить полную и инкрементальную записи одной базы в одном каталоге и выбирать только одну из них для запуска. Если обе отмечены, одинаковые каталоги блокируют запуск.

«Последнее изменение» — дата последнего коммита локального Git по этому каталогу. Это ориентир по истории, а не гарантированная дата выгрузки. При отсутствии Git, репозитория или коммитов отображается «—». Наведите мышь на ячейку для пояснения.

Список расположен в группе «Информационная база».

«Добавить» — новая запись.
«Редактировать» — параметры выбранной записи; также можно дважды щёлкнуть строку.
«Удалить» — убрать выбранную запись из списка. База и файлы на диске не удаляются.

Флажок строки определяет участие в обработке. Если он снят, база пропускается. При одной отмеченной базе выполняется обычная очередь из одной строки.

У каждой конфигурации должен быть свой каталог. Одинаковые каталоги выбранных строк блокируют запуск, чтобы избежать смешивания файлов.

Сохраняются все параметры и флажки выбора. Статусы обработки относятся к текущему сеансу.

## Подключение и авторизация базы

В форме базы укажите название записи. Зарегистрированную базу можно выбрать из списка Windows; поля подключения заполнятся автоматически.

Для ручного подключения:
• «Файловая» — каталог базы, а не путь к отдельному файлу.
• «Серверная» — сервер и имя базы отдельно.

Поле «Заполнить параметры подключения из строки подключения» принимает примеры:

Srvr="srv-1c";Ref="upp";

File="C:\cgtp\базы\пустая";

Нажмите «Заполнить», чтобы разобрать строку. Она заполняет только подключение, а не пароли и параметры выгрузки.

Пользователь/пароль 1С — авторизация конфигуратора. Пустое имя означает авторизацию 1С по умолчанию.

Пользователь/пароль хранилища — хранилище конфигурации 1С. База должна быть подключена к нему заранее. Если хранилище не используется, оставьте эти поля пустыми. Это не реквизиты GitHub.

## Каталог и режим выгрузки

Сообщение коммита задаётся в форме параметров каждой базы. По умолчанию используются «Полная выгрузка конфигурации 1С» и «Инкрементальная выгрузка конфигурации 1С». При переключении режима поле показывает соответствующий текст. Ваши изменения сохраняются отдельно для каждого режима и входят в снимок автоматического сценария. Ранее заданное общее сообщение переносится в записи баз с указанием режима.

Каталог файлов / Git задаётся отдельно для каждой базы в её форме. Несуществующий каталог создаётся при запуске обработки.

Режим выгрузки выделен цветом и жирным шрифтом:

• Начальная (полная) — для первой выгрузки и получения полной копии.
• Инкрементальная — обновление изменений в предыдущей выгрузке той же базы. Нужен ConfigDumpInfo.xml в выбранном каталоге.

Без ConfigDumpInfo.xml выберите полную выгрузку. При смене конфигурации используйте другой каталог. Полная выгрузка может заменять ранее выгруженные файлы.

## Общие параметры выгрузки

Группа «Выгрузка» под списком содержит общий фильтр размера и лимит в мегабайтах для всех отмеченных баз.

Индивидуальные флажки коммита/отправки, каталоги, репозитории и режимы задаются в форме каждой базы.

## Фильтр больших файлов

Фильтр включён по умолчанию, лимит — 30 МБ. Если уже сохранены настройки, восстанавливается предыдущий выбор. Один мегабайт здесь равен 1 048 576 байтам.

После успешной выгрузки, до коммита, удаляются созданные или изменённые текущей выгрузкой файлы строго больше лимита. Файл ровно на границе остаётся. Лимит применяется к каждому файлу отдельно, а не к сумме файлов объекта.

Неизменённые ранее существовавшие файлы, данные .git и журнал не удаляются. Удалённые пути фиксируются в журнале. При инкрементальном режиме неизменённые файлы заново не фильтруются.

Результат с включённым фильтром НЕ является полной копией для восстановления конфигурации. Чтобы получить все файлы, отключите фильтр и выполните полную выгрузку.

Фильтр не очищает старые коммиты Git.

## Git и GitHub

Для простой выгрузки оставьте коммит и отправку выключенными в форме базы.

Если нужен коммит:
1. Укажите работающий git.exe в общих настройках.
2. В форме базы включите коммит.
3. Настройте имя и email автора в самом Git.
4. Заполните сообщение коммита в форме параметров базы. Для полной и инкрементальной выгрузки тексты сохраняются отдельно.

После подтверждения запуска, если репозитория в каталоге нет и его можно создать, утилита создаёт локальный репозиторий с веткой main. Имя базы записывается в .git/config. Каталог не переименовывается, удалённый репозиторий GitHub не создаётся.

Для GitHub:
1. В общих настройках укажите логин и personal access token, затем «Применить».
2. В форме базы выберите репозиторий из заранее загруженного списка либо впишите владелец/имя.
3. Включите отправку после выгрузки и коммита.

Токен должен иметь доступ ко ВСЕМ используемым репозиториям. Для fine-grained токена выберите All repositories либо включите каждый нужный репозиторий в Selected repositories. Требуется разрешение Contents: Read and write. Пароль аккаунта вместо токена не подходит.

Список показывает репозитории, доступные общему токену. При загрузке уже выбранное значение не сбрасывается.

После сохранения настроек с логином и токеном утилита автоматически пытается загрузить список и сохраняет кеш. Каждая новая форма базы сразу использует его. «Обновить…» с иконкой обновления повторяет запрос вручную. Ошибка обновления отображается в журнале, ранее сохранённые параметры не теряются.

В Git добавляются изменения в пределах каталога выгрузки, исключая 1c-dump.log. Пустой коммит не создаётся. Отправляется текущая ветка обычным push; принудительной перезаписи истории нет. При отказе GitHub локальный коммит сохраняется.

## Автоматическое согласование GitHub: локальный снимок имеет приоритет

Начиная с v.2.5.2 при отказе non-fast-forward / fetch first утилита автоматически согласует истории и повторяет отправку один раз. Это работает и в GUI, и в автоматическом сценарии при включённой отправке на GitHub. Дополнительный флажок не требуется.

Источник истины — уже созданный локальный коммит после выгрузки, проверки и фильтра размера. Правило относится ко всему Git-репозиторию, включая файлы вне каталога выгрузки, если каталог вложен в более крупный репозиторий. Удалённые правки и файлы не подмешиваются в текущий снимок. Файлы только удалённой версии исчезнут из актуального состояния ветки, но сохранятся в истории Git.

Сначала выполняется обычный push. Только при отказе из-за истории утилита проверяет текущую ветку, неизменность HEAD, индекс и рабочие отслеживаемые файлы всего репозитория. Незавершённые merge/rebase/cherry-pick/revert/bisect и index.lock блокируют согласование. Неподготовленные служебные файлы .onecexporter.lock и 1c-dump.log не мешают; чужие staged-изменения или изменённые отслеживаемые файлы нужно сохранить вручную.

Затем получает выбранную удалённую ветку с тем же токеном GitHub во временную уникальную ссылку (не в FETCH_HEAD). Если удалённая история ещё не входит в локальную, создаёт две локальные резервные ветки onecexporter-backup/…/local и …/github. Их имена записываются в журнал. Создаёт merge-коммит с --no-ff --allow-unrelated-histories --strategy=ours. Это не -X ours: файлы берутся целиком из локального коммита, а обе истории сохраняются.

Перед повторной отправкой проверяются точное совпадение Git-дерева файлов с первоначальным снимком, наличие обеих исходных историй в итоговом коммите, текущая ветка и чистота индекса/отслеживаемых файлов. Отправляется проверенный идентификатор коммита, а не изменяемый HEAD. Временная ссылка удаляется с проверкой её ожидаемого значения; резервные ветки остаются локально и автоматически не отправляются. Их можно удалить вручную после проверки результата.

Ровно одна повторная отправка; при новом отказе обработка завершается ошибкой, без циклических повторов. Ошибки токена, защищённой ветки и лимита размера файлов этим способом не устраняются. Force-push, reset --hard, удаление lock и автоматический откат не применяются. При отмене/сбое проверьте журнал и состояние Git; временная ссылка или незавершённая операция могут остаться.

Предпубликационные защиты: assume-unchanged/skip-worktree проверяются до экспорта и коммита, чтобы Git не пропустил изменённые файлы. При отправке проверяется весь индекс. refs/replace и info/grafts блокируются: переопределённые истории требуют ручной проверки. Такие флаги/ссылки утилита не удаляет автоматически. Подмены адреса через insteadOf, pushInsteadOf и remote с именем полного URL запрещены до запуска сетевой команды. Для слияния явно заданы commit/no-squash/no-autostash; подписи и хуки остаются действующими. Повторный контроль отмены не допускает запуск новой команды после полученного запроса остановки.

Первое получение удалённой истории может скачать большой объём объектов и занять место на диске. Для fetch установлен тайм-аут 30 минут, для отдельной отправки — 5 минут; общий тайм-аут сценария также действует. Фильтр размера текущей выгрузки не уменьшает существующую историю. Не меняйте ветку и не выполняйте другие команды Git параллельно с утилитой. В сводке этапов отображаются резервные ветки, успешное согласование и успешная отправка отдельно.

## Настройки и индикаторы

Утилита требует Windows с .NET Framework 4.8 и установленной платформой 1С.

«Настройки» открывает отдельное окно:
• установленная платформа из найденных версий либо полный путь к 1cv8.exe;
• расположение git.exe;
• общий логин и токен GitHub.

«Применить» проверяет и сохраняет значения. «Отмена» не применяет изменения.

Индикаторы рядом:
• Платформа: зелёная галочка — файл найден; красный крестик — не выбрана/не найдена.
• Git: зелёная галочка — запускается; синий кружок — путь не задан; красный крестик — недоступен или выбран неверный файл.
• GitHub: зелёная галочка — логин и токен подтверждены; синий кружок — не заполнены/проверяются; красный крестик — ошибка соединения или авторизации.

При наведении на значок появляется объяснение. Проверки выполняются при запуске и применении настроек. Зелёный GitHub подтверждает авторизацию, но права записи проверяются при отправке.

## Выполнение, результаты и остановка

Базы выполняются строго по очереди: выгрузка → фильтр → коммит → отправка, если соответствующие этапы включены для записи. Ошибка одной базы не отменяет следующие.

В строке:
• синий значок — выполняется;
• зелёная галочка — все выбранные этапы успешны;
• красный крестик — ошибка. Причина находится в «Пояснение» и подсказке при наведении.

Список создаваемых/изменяемых файлов находится под группой «Выгрузка» и показывает последние 200 уведомлений Windows для текущей базы. Это не полный перечень конфигурации и не точный порядок обработки объектов.

Полоса прогресса отражает завершённые этапы текущей базы. Точный процент внутри обычного запуска DESIGNER /DumpConfigToFiles недоступен.

«Остановить» завершает текущий конфигуратор и отменяет оставшуюся очередь. Во время этапа Git/GitHub необходимо дождаться его завершения. После прерывания файлы текущей базы могут представлять частичную выгрузку.

## Журнал и ошибки

Вкладка «Журнал» содержит команду с замаскированными паролями и сообщения обработки по базам.

Файлы:
• 1c-dump.log — в каталоге соответствующей базы, сообщения 1С.
• exporter-events.log — рядом с exe; запуск под пользователем, PID, завершение с кодом и ответы Git.

Типичные ошибки:
• 1cv8.exe не найден — исправьте путь в «Настройках».
• Git не найден — исправьте путь либо отключите коммит для записи.
• Нет ConfigDumpInfo.xml — выберите полную выгрузку.
• Нет соединения с хранилищем — проверьте подключение базы к хранилищу 1С или очистите его реквизиты.
• Ненулевой код конфигуратора — читайте причину в журнале; проверьте базу, авторизацию и права.
• GitHub HTTP 401 — проверьте токен и логин, повторно примените настройки.
• Push отклонён — проверьте права, ветку и историю. Коммит сохраняется локально.
• GH001 / файл больше 100 МБ — крупный файл присутствует в отправляемой истории. Фильтр текущих файлов не очищает старые коммиты; удаление новым коммитом не помогает. Требуется отдельная подготовка неотправленной истории либо новый репозиторий с отфильтрованными файлами.
• Ошибка каталога/сохранения — проверьте путь и право записи.

## Как устранить ошибку Git перед выгрузкой

Двойной щелчок по статусу или пояснению ошибочной строки открывает причину и раздел «Как продолжить». Для ошибок этапа Git в нём есть команды с уже подставленными путями к git.exe и каталогу базы. Команды предназначены для Windows PowerShell, не для cmd.exe или Git Bash. Кнопки внизу окна копируют отдельную команду; «Копировать пояснение» копирует весь текст. Утилита не выполняет эти команды автоматически.

Если в индексе уже есть подготовленные изменения, сначала проверьте их. Затем выберите один вариант:
• «Копировать снятие с индекса» — отменяет подготовку файлов каталога выгрузки к коммиту, не удаляя и не изменяя файлы на диске. Файлы других каталогов и служебные журналы не затрагиваются. Для существующей истории используется restore --staged, для репозитория без первого коммита — rm --cached. Команда сначала проверяет различия рабочих файлов и индекса. При различиях она отказывается снимать подготовку, чтобы не потерять промежуточную подготовленную версию: сначала сохраните её коммитом. Принудительные ключи не используются.
• «Копировать команду коммита» — сохраняет ВСЕ уже подготовленные изменения репозитория отдельным коммитом, в том числе вне каталога выгрузки. Перед запуском изучите diff --cached --stat и при необходимости сам diff. Утилита не добавляет файлы и не выбирает их за вас.

Не выполняйте команды изменения репозитория, пока утилита или другой процесс работает с ним. После устранения причины повторите обработку нужной базы. При merge/rebase/конфликтах сначала завершите текущую операцию по подсказкам git status. При index.lock убедитесь, что никакой Git не работает: удаление живой блокировки опасно. Не применяйте reset --hard, clean -fd или force-push без проверки и резервной копии.

Внизу «Настроек» доступны ссылки «Скачать Git для Windows» (официальный сайт Git) и «GitHub». Они открываются в браузере по умолчанию, не устанавливают программы и не передают введённые реквизиты.

## Автоматический сценарий и Планировщик Windows

1. Настройте очередь и отметьте строки для автоматического выполнения.
2. Нажмите «Сохранить как сценарий» и выберите место сохранения .ps1.
3. Рядом появится отдельный файл .settings.dat — зашифрованный снимок базы/паролей/путей/режимов/токена. Не удаляйте его.
4. Проверьте сценарий вручную под учётной записью, которая будет выполнять задачу.
5. Создайте задачу в Планировщике Windows с нужным расписанием.

Программа действия: powershell.exe.
Аргументы: -NoProfile -ExecutionPolicy RemoteSigned -File "C:\путь\Export-1C.ps1"
Необязательный аргумент: -TimeoutMinutes 240 (по умолчанию — 180 минут на весь запуск).

Организационная политика исполнения скриптов имеет приоритет. Если требуется, подпишите сценарий. Не включайте одновременный запуск экземпляров одной задачи: в параметрах задачи выберите «Не запускать новый экземпляр». Сам скрипт также использует блокировку от одновременного запуска того же снимка.

Сценарий запускает exe утилиты без окна и подтверждений. Утилита, выбранная платформа и Git должны оставаться доступными по сохранённым путям. При необходимости путь к exe можно переопределить параметром -UtilityExe.

Запускайте под тем же пользователем Windows на том же компьютере: это требуется для расшифровки DPAPI. Учётная запись должна иметь доступ к базам, каталогам и своим Git-настройкам. Для другого сервера заново настройте утилиту и создайте сценарий на сервере.

Скрипт не содержит паролей или токена открытым текстом. Все реквизиты — в защищённом файле.

Коды завершения:
• 0 — все выбранные записи успешны.
• 1 — хотя бы одна запись завершилась с ошибкой.
• 2 — ошибка запуска/настроек/расшифровки.
• 124 — превышен тайм-аут; скрипт остановил утилиту и её дочерние процессы.

Рядом со сценарием создаётся .result.json с временем, статусами и причинами по строкам. Проверяйте время отчёта: после принудительного прерывания там может остаться прежний результат. Сообщения конфигуратора — в каталогах баз; exporter-events.log — рядом с exe.

Снимок независим от текущего списка GUI. После изменения задач создайте сценарий заново. Кнопка создаёт файлы, но не регистрирует задачу в Планировщике автоматически.

## Сохранение и справка

«Сохранить настройки», применение общих настроек, изменение списка и окончание обработки сохраняют settings.dat рядом с exe. Список и реквизиты баз зашифрованы Windows DPAPI для текущего пользователя.

На другом компьютере или под другим пользователем реквизиты нужно ввести заново. Отсутствие файла не вызывает ошибок. Повреждённый файл не мешает запуску и не заменяется автоматически; его можно заменить явным сохранением.

«Справка» или F1 открывает эту встроенную инструкцию. Слева — содержание и поиск, справа — текст. Esc или «Закрыть» закрывает окно. Интернет и отдельный файл не нужны; копия UsageGuide.md включена в архив.

## Ограничения и защита при выполнении

Каталоги отмеченных баз не должны совпадать или быть вложенными друг в друга. Каталог выгрузки не должен содержать утилиту или пересекаться с файловой базой.

В окне показывается ограниченный объём журнала, для 1С читается конец файла размером до 256 КиБ. Полный 1c-dump.log остаётся в каталоге выгрузки. Ответы Git ограничиваются 256 тысячами символов на поток; сокращение отмечается в журнале. exporter-events.log при превышении 10 МиБ переносится в exporter-events.log.previous; сохраняется один предыдущий файл.

Git имеет тайм-аут: отправка — 5 минут, остальные операции — 30 минут. Кнопка «Остановить» действует также на текущий процесс Git. Прерывание Git может оставить незавершённую операцию или файл блокировки: проверьте репозиторий перед повторным запуском.

Утилита v.2.5 блокирует одновременно работающие выгрузки в один каталог и во вложенные каталоги через служебный файл .onecexporter.lock. Файл остаётся после завершения: это нормально, занятость определяется открытым дескриптором, а не наличием файла. Не удаляйте его во время работы. Старые версии утилиты и ручные команды 1С эту блокировку не учитывают.

## Просмотр результатов во время работы

Во время выполнения список остаётся доступным для просмотра и выделения строк, но менять флажки и параметры нельзя. Наведите указатель на «Статус» или «Пояснение», чтобы увидеть причину ошибки. Двойной щелчок по этим колонкам открывает окно с полным пояснением и возможностью скопировать текст. Во время обработки двойной щелчок по любой ячейке открывает пояснение, а не редактирование базы. Очередь продолжает работу, пока окно пояснения открыто; сводка завершённых этапов и текущий этап обновляются автоматически.

В разделе «Журнал» вкладка «Команды запуска» хранит команды всех попыток запуска конфигуратора текущей очереди с названием базы, временем и режимом. Пароли скрыты. История очищается только перед новой очередью; изменение параметров не заменяет ранее записанные команды. Если база не дошла до запуска конфигуратора из-за ошибки подготовки, команды для неё нет — причина указана в списке.

Соседняя вкладка «Журнал выполнения» содержит сообщения 1С, события и результаты Git/GitHub. Переход к следующей базе не переключает выбранную вкладку. Для очень длинной очереди действует ограничение отображаемой истории команд до 256 тысяч символов.

## Краткий и подробный журналы Git

«Журнал выполнения» показывает краткий вывод Git. Повторяющиеся предупреждения о замене LF/CRLF сворачиваются в одну строку с количеством предупреждений. Проверка изменений показывает число путей вместо полного списка. В выводе коммита сохраняются итоговые строки, а перечень созданных, удалённых, скопированных и переименованных файлов сворачивается в сводку. Неизвестные предупреждения и сообщения об ошибках не фильтруются.

Фильтрация выполняется по мере чтения процесса, до ограничения объёма текста. Поэтому тысячам предупреждений о переносах строк не удаётся вытеснить настоящую ошибку, появившуюся после них.

«Открыть подробный журнал Git» открывает git-details.log рядом с exe в Блокноте. В файле сохраняются строки stdout/stderr с указанием потока, имени базы и команды, включая свёрнутые в интерфейсе строки. Известные пароли и токен маскируются. Файл ротируется при превышении 10 МиБ, остаётся одна предыдущая копия git-details.log.previous. Это ограниченная история, а не бессрочный архив. Строки свыше 65536 символов скрываются целиком с отметкой, чтобы избежать чрезмерного расхода памяти и частичного раскрытия секретов. При невозможности записи подробного журнала интерфейс показывает предупреждение; чтение процесса продолжается.

## Сводка этапов обработки

Окно пояснения показывает отдельно уже завершённые этапы и текущую операцию: выгрузка файлов, проверка основных файлов, фильтр размера, создание коммита и отправка на GitHub. Пункты добавляются только после успешного завершения соответствующего этапа. При ошибке отправки будет видно, что выгрузка и локальный коммит уже выполнены. Если изменений нет, вместо «создан коммит» выводится «Новых изменений нет — коммит не создавался».

Проверка выгрузки подтверждает наличие Configuration.xml и ConfigDumpInfo.xml, возможность их чтения и XML-корневого элемента. Это базовая проверка, не полная проверка всех объектов или возможности загрузки конфигурации. Она выполняется перед фильтром размера и Git.

## Защитные проверки v.2.5

Используйте абсолютный путь к отдельному обычному каталогу. Корень диска/сетевого ресурса, .git, пути со ссылками/junction и пересекающиеся с файловой базой каталоги не допускаются. Ссылки внутри каталога также вызывают отказ до запуска конфигуратора. Проверка каталогов выполняется в фоне, чтобы окно оставалось отзывчивым.

До работы Git утилита проверяет незавершённый merge/rebase/cherry-pick, конфликты и index.lock. Уже подготовленные изменения в каталоге выгрузки нужно сохранить или убрать из индекса вручную. Чужие подготовленные изменения вне каталога не включаются в коммит. Утилита не снимает блокировки Git и не завершает его операции автоматически.

Отправка с токеном запрещается при наличии url.insteadOf: это исключает незаметную подмену адреса. Для Git очищаются унаследованные GIT_/GCM_ параметры, используется проверка TLS и запрещаются HTTP-перенаправления с токеном. Доверяйте выбранному git.exe, платформе и настройкам/хукам локального репозитория.

Фильтр не удаляет Configuration.xml, ConfigDumpInfo.xml, служебные файлы Git, блокировку, сценарии и снимки настроек. Их размер не отменяет их необходимости для последующей работы. Проверка XML ограничена 128 МиБ символов на документ и не является полной проверкой восстановимости конфигурации.

Настройки ограничены 1000 базами, 10000 репозиториями и размером файла 4 МиБ. Переносы строк в реквизитах не допускаются. При изменении файла настроек другим экземпляром автоматическое сохранение отменяется; явное сохранение предлагает подтвердить замену. Во время автоматического запуска снимок настроек не переписывается.

Сохранение сценария использует блокировку его снимка, поэтому заменить выполняемый сценарий нельзя. При запуске отчёт получает состояние Running, при завершении — Completed; оболочка пишет Failed/TimedOut при сбоях запуска или тайм-ауте. Файл отчёта заменяется атомарно. Ориентируйтесь на State, ExitCode и время нового отчёта, а не только на существование файла. При отказе взять блокировку сценарий не перезаписывает отчёт другого запуска.

Получение репозиториев ограничено 60 секундами на весь список, ответ — 2 МиБ. При закрытии окна запросы отменяются. Если наблюдение за создаваемыми файлами недоступно, это фиксируется в журнале; сама выгрузка продолжается.
