# Финальное ревью v.2.5 — 08.10.2026

Исправлены обнаруженные ошибки исполнения, риски потери данных, зависания и утечки ресурсов. Ревью не является доказательством отсутствия всех ошибок. Рабочие базы 1С и отправка на GitHub не использовались в проверках.

## Существенные исправления

1. Остановка на этапе Git выбирала уже завершившийся процесс 1С. Теперь выбирается активный Git, остановка дерева выполняется вне UI-потока, отменяется оставшаяся очередь.
2. Разные экземпляры могли одновременно писать в один каталог. Добавлена эксклюзивная файловая блокировка, включая проверки родительских/вложенных каталогов после её получения. Файл .onecexporter.lock не удаляется и исключён из Git/фильтра.
3. Псевдонимы и ссылки могли обходить текстовую проверку путей. Существующая часть пути разрешается через Windows GetFinalPathNameByHandle; запрещены относительные пути, корни ресурсов, .git и reparse points. Проверки каталогов выполняются в фоне, большие обходы ограничены и отменяемы.
4. Фильтр мог удалить Configuration.xml/ConfigDumpInfo.xml и служебные файлы сценария. Метаинформация, блокировки, .gitignore/.gitattributes/.gitmodules, сценарии и снимки защищены. Размер повторно проверяется перед удалением; отмена учитывается при обходе.
5. Снимок фильтра хранил строковые отметки для каждого файла. Используются две числовые отметки; обход ограничен 500000 файлами. Это снижает расход памяти, но большие конфигурации всё равно требуют значительного объёма RAM.
6. Подготовленные вручную изменения в каталоге могли быть затронуты автоматическим коммитом. До экспорта проверяются staged-изменения, конфликты, merge/rebase/cherry-pick/revert и index.lock. Утилита не исправляет эти состояния сама.
7. Унаследованные GIT_DIR/GIT_WORK_TREE/GIT_INDEX_FILE/GIT_CONFIG_* могли перенаправлять операции. Дочернему Git передаётся очищенная среда. Проверены подстановка GIT_DIR и дубли PATH/Path; последние вызывали реальную ошибку запуска .NET Framework и теперь нормализуются без изменения среды родительского процесса.
8. При отправке проверяется TLS, запрещаются перенаправления и url.insteadOf. Перед установкой собственного заголовка авторизации очищается предыдущий URL-специфичный extraHeader; credential.helper и интерактивные запросы отключены для отправки.
9. stdout и stderr смешивались и могли испортить имя ветки/результат status. При успешном выполнении в логику передаётся stdout, а предупреждения stderr остаются в журнале. Ненулевой код и ошибки не скрываются.
10. Диагностические Git-команды читали неограниченный вывод и могли зависнуть на дочерних потоках. Потоки ограничены, одновременно дренируются; ожидание процесса — 5 секунд, закрытия потоков — 2 секунды. Основные команды имеют тайм-аут; ненужные таймеры отменяются, ошибки фоновых задач наблюдаются.
11. Вся выгрузка могла провалиться из-за недоступного FileSystemWatcher. Наблюдатель теперь необязателен: отказ фиксируется, экспорт продолжается. Очередь уведомлений ограничена под блокировкой, старые события не переходят в следующую базу.
12. Ошибка одной строки вне основного экспорта могла оборвать очередь. Добавлена отдельная граница try/catch/finally на базу с освобождением её блокировки и записью причины подготовки.
13. Старый журнал 1С оставался при ошибке удаления и мог выдавать устаревшую причину. Невозможность подготовить новый журнал теперь останавливает запуск с явной ошибкой.
14. Чтение конца живого журнала могло показывать частично записанные секреты. Незавершённая строка не показывается до окончания/переноса; начальный обрыв строки отбрасывается. В Git чрезмерно длинная строка скрывается целиком.
15. Настройки могли сохраниться в размере, который утилита затем не читала. Ограничены размер шифротекста/JSON, совокупность полей, отдельные поля и реквизиты; исключены NUL и переносы строк в авторизации. Чтение ограничивается через открытый файл, а не отдельный предварительный stat.
16. Автоматический запуск переписывал собственный снимок. Он больше не сохраняет настройки. GUI проверяет подпись именно прочитанного файла; чужие изменения не перезаписываются автоматически. Явное сохранение предлагает подтверждение.
17. Перезапись снимка выполняемого сценария и сбой между записью двух файлов могли испортить пару. Генератор использует тот же lock, предварительное шифрование и атомарную замену; при обычной ошибке восстанавливается старый снимок. Ошибка восстановления не замалчивается.
18. После неудачного запуска/тайм-аута оставался прежний успешный JSON. Добавлены состояния Running/Starting/Completed/Failed/TimedOut и атомарная запись. Отчёт не может заменять настройки, сценарий обязан иметь расширение .ps1. Проверена UTF-8 BOM для Windows PowerShell.
19. Сетевой запрос списка репозиториев мог продолжаться до 25 минут и получать неограниченное тело. Весь запрос ограничен 60 секундами, одно тело — 2 МиБ, страницы — 100 записей. Перенаправления отключены, запросы отменяются при закрытии; одновременное получение одного списка объединяется.
20. Async-ошибка обработчика могла завершить GUI. Запуск очереди/настроек/инициализация имеют перехват ошибки с журналом и объяснением. Поздние сетевые ответы не изменяют новое подключение; фоновое обновление не заменяет статус работающей очереди.
21. Даты Git могли создавать длинную очередь фоновых процессов. Есть общий бюджет 60 секунд и отмена устаревшего обновления; во время выгрузки обновление дат не стартует.
22. Шрифты, изображения, скрытые контролы и таймеры освобождаются однократно. Форма справки переиспользует шрифты вместо создания новых при каждом выборе раздела.
23. Зарегистрированные базы читались только как UTF-8. Добавлена поддержка UTF-16 LE/BE и Windows-1251, ограничены размер файла и строки; разбор строки подключения ограничен по длине/времени.
24. В редакторе недоступные флажки могли остаться включёнными без возможности снять их. Недоступные Git/GitHub операции показываются снятыми, доступны подсказки; изменения применяются при сохранении записи.
25. При удалении записи предлагается подтверждение; база и файлы не удаляются. Число записей ограничено уже в GUI. Платформа проверяется как существующий 1cv8.exe. Сборка считает предупреждения ошибками.

Ранее выполненные исправления сохранены: краткие сводки LF/CRLF и файлов Git, отдельный маскированный подробный журнал, история команд всех баз, живое пояснение этапов, сообщения коммита отдельно по базам/режимам и миграция старых настроек.

## Проверки

- Сборка .NET Framework без предупреждений.
- VerifyFinalSafety: версия 2.5; опасные/вложенные пути; занятые каталоги; parent/child-блокировки; junction; фильтр и метаинформация; отмена; размеры настроек; конфликт сохранения; неизменяемый снимок; JSON и защита коллизии; BOM/lock сценария; staged/merge; GIT_DIR; URL rewrite; ограниченный поддельный HTTP без сети.
- VerifyCancellation: активный медленный тестовый Git после завершения фиктивной 1С; правильный процесс для остановки; завершение дочернего процесса; пропуск очереди; освобождение полей; неизвестное предупреждение stderr не выдаётся за изменение файлов.
- VerifyMessages/Review/GitExecution/GitLog/RunUi: режимы сообщений, DPAPI и миграция, кодировки и пределы журналов, 5000 предупреждений с поздней ошибкой, настоящий локальный add/commit/status, доступность пояснения во время очереди.
- VerifyStages/Automation: завершённые этапы и реальные тестовые коммиты, отсутствие изменений, ошибки/пропуски, CLI-коды и дата коммита.
- Сгенерированный сценарий выполнен Windows PowerShell, в том числе с пробелом и апострофом в имени файла; итоговый JSON содержит Completed и ExitCode 0.

Тесты создают собственные каталоги и репозитории. В ограниченном контексте DPAPI может не иметь загруженного профиля; криптографические тесты выполнены под текущим пользователем Windows. GitHub заменялся поддельным HTTP-ответом, 1С — фиктивным процессом; проверки не подтверждают совместимость со всеми версиями настоящей платформы, серверами и лицензированием.

## Оставшиеся ограничения

- Нет полной транзакции экспорта: сбой 1С/диска/питания может оставить частичный каталог. После такого сбоя рекомендуется полная выгрузка.
- Атомарная замена одного файла не делает пару сценарий/настройки транзакцией при отключении питания. Зафиксированная ошибка отката требует ручной проверки файлов.
- Блокировки учитывают только экземпляры v.2.5. Старые утилиты, ручной конфигуратор/Git и сторонние программы могут изменять каталог. Не удаляйте lock во время работы; не заменяйте пути/ссылки извне. Это не файловая песочница, защита от злоумышленника с правами того же пользователя/администратора или от всех гонок/жёстких ссылок.
- Git-хуки, фильтры и выбранные EXE являются доверенным кодом и могут исполняться под вашим пользователем. Предварительная проверка не гарантирует, что сторонний Git не изменит индекс после неё.
- kill/taskkill может не завершить процесс при недостатке прав или сбое ОС. После ошибки остановки/тайм-аута проверьте процессы и index.lock; утилита не удаляет блокировки автоматически.
- Вызов ОС к недоступному сетевому файловому ресурсу может долго ожидать даже после запроса отмены; фоновые проверки сохраняют отзывчивость GUI, но не гарантируют мгновенное завершение системного I/O.
- Ручной экспорт не имеет фиксированного тайм-аута; сценарий ограничивает всю очередь. Процент байтов заранее неизвестен: прогресс показывает этапы.
- Проверка основных XML ограничена 128 МиБ символов на документ и не подтверждает корректность всех объектов/восстановимость базы.
- Фильтр делает выгрузку неполной; он не удаляет крупные файлы из истории Git. GitHub может отклонить старую историю или защищённую обязательную метаинформацию большого размера.
- Пароли 1С передаются в командной строке по протоколу платформы; токен Git — в среде дочернего процесса. DPAPI и маскирование не защищают от программ того же пользователя, администраторов и дампов памяти.
- Журналы ограничены/ротируются; это не бессрочный аудит. Межпроцессная запись общего журнала может временно не удаться и отмечается там, где возможно.

Версия 2.5 установлена в заголовке, справке, AssemblyVersion/AssemblyFileVersion и манифесте. Формат настроек v1 сохранён.

Полный набор из девяти тестов успешно выполнен через включённый test.ps1 из каталога поставки. В ходе регрессии дополнительно исправлено исключение .onecexporter.lock из add/commit (первоначально оно было применено только к status). Тестовые артефакты в архив не входят.

## Дополнение: помощь при ошибках Git

Добавлены инструкции и копирование PowerShell-команд без автоматического изменения репозитория. Проверки конфликтов выполняются до проверки обычных подготовленных изменений, чтобы не предлагать снятие с индекса при неразрешённом конфликте.

Команда снятия с индекса ограничена каталогом выгрузки, исключает служебный журнал и блокировку. Перед изменением она проверяет различия индекса и рабочих файлов: если промежуточная подготовленная версия отличается, команда отказывается её терять. Учтён репозиторий без HEAD; прочие ошибки проверки не переходят к ветке rm --cached. Команда коммита явно сопровождается предупреждением о ВСЕХ подготовленных изменениях репозитория. Перезапись истории, force, очистка рабочих файлов и автоматическое удаление index.lock не предлагаются.

GitRecovery не запускает процессы; в команды включаются только выбранные пути, с экранированием одинарных кавычек для PowerShell. Пароли и токены в команды не включаются. Ссылки в настройках фиксированы и не содержат реквизитов.

Новый VerifyGitRecovery проверяет команды в реальных временных репозиториях с начальной и существующей историей, сохранность рабочих файлов и чужих подготовленных изменений, отказ терять промежуточную версию, специальные символы/кириллицу в пути, вывод рекомендаций по нужной строке и размещение кнопок в компактном окне. Набор расширен до десяти проверок. Команды предназначены для Windows PowerShell; пользователь должен выполнять их после окончания работы других процессов с репозиторием. Эта инструкция не устраняет гонки со сторонними процессами и не заменяет резервные копии.
