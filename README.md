# OneEsConfigExporter

[![Windows CI](https://github.com/Ipslor/OneEsConfigExporter/actions/workflows/windows-ci.yml/badge.svg)](https://github.com/Ipslor/OneEsConfigExporter/actions/workflows/windows-ci.yml)

![Platform](https://img.shields.io/badge/platform-Windows-blue)
![Runtime](https://img.shields.io/badge/.NET_Framework-4.8-512BD4)

Portable-утилита для Windows: выгрузка конфигураций **1С:Предприятие 8** в файлы, локальные Git-коммиты и отправка на GitHub. Приложение написано на C# / WinForms и не требует установки.

Очередь обрабатывает отмеченные базы последовательно — от одной конфигурации до нескольких. Версия приложения: **v.2.5**.

## Скачать

Готовая сборка и исходники: [GitHub Releases](https://github.com/Ipslor/OneEsConfigExporter/releases).

Распакуйте portable ZIP в доступную для записи папку и запустите `OneCConfigExporter.exe`. Не запускайте EXE прямо из архива. Настройки и журналы сохраняются рядом с ним.

> При обновлении сохраните свой `settings.dat`. Закройте старую утилиту перед заменой EXE. Уже созданные автоматические сценарии рекомендуется пересоздать.

## Возможности

- Список зарегистрированных баз 1С и ручное подключение к файловой/серверной базе.
- Заполнение подключения из строк `File="C:\Bases\Demo";` и `Srvr="srv-1c";Ref="demo";`.
- Очередь с флажками, добавлением, редактированием, удалением и копированием записей.
- Полная и инкрементальная выгрузка через `DESIGNER /DumpConfigToFiles`; подавление стартовых диалогов.
- Авторизация в базе и хранилище конфигурации 1С.
- Выбор установленной платформы, пути к `git.exe` и параметров GitHub в настройках.
- Необязательные локальный коммит и отправка в выбранный GitHub-репозиторий.
- Отдельные сообщения коммита для полной/инкрементальной выгрузки каждой базы.
- Фильтр крупных созданных/изменённых файлов, по умолчанию включён с лимитом 30 МБ.
- Живая сводка этапов, причины ошибок, история команд и краткий/подробный журналы.
- Сохранение настроек через Windows DPAPI и создание PowerShell-сценария для Планировщика Windows.
- Защитные проверки каталогов, блокировки параллельных выгрузок и незавершённых операций Git.

## Требования

| Компонент | Для чего нужен |
| --- | --- |
| Windows с .NET Framework 4.8 | Запуск GUI и автоматического режима |
| Установленная платформа 1С, `1cv8.exe` | Запуск конфигуратора и экспорт |
| Доступ к базе и возможность запуска конфигуратора | Выполнение выгрузки |
| Git for Windows | Только для локального коммита и GitHub |
| GitHub personal access token | Только для отправки и получения списка репозиториев |

Токен должен иметь доступ ко всем выбранным репозиториям и разрешение на запись содержимого. Git и GitHub не нужны для простой выгрузки в каталог.

## Быстрый старт

1. Откройте **Настройки**, выберите платформу 1С. При необходимости укажите Git и GitHub.
2. Нажмите **Добавить**, выберите зарегистрированную базу или задайте её параметры вручную.
3. Укажите отдельный каталог выгрузки и режим: **полная** либо **инкрементальная**.
4. Заполните пользователя/пароль базы и хранилища, если они нужны.
5. При необходимости включите коммит, задайте сообщение и выберите GitHub-репозиторий.
6. Отметьте нужные строки и нажмите **Выполнить**.
7. Во время работы наведите указатель на статус или откройте пояснение двойным щелчком. Изменение очереди заблокировано, просмотр доступен.

Подробная инструкция встроена в **Справка / F1** и находится в [UsageGuide.md](UsageGuide.md).

### Полная и инкрементальная выгрузка

Для первой выгрузки используйте полный режим. Инкрементальный режим требует `ConfigDumpInfo.xml` от предыдущей выгрузки той же конфигурации. Нельзя одновременно обрабатывать записи с одинаковыми или вложенными каталогами.

> **Фильтр размера делает выгрузку неполной.** Для полной копии, пригодной к последующему восстановлению, отключите фильтр и выполните полную выгрузку. Фильтр работает с отдельными файлами, а не суммарным размером объекта, и не очищает историю Git от прежних крупных файлов.

### Git и GitHub

При включённом коммите утилита проверяет каталог и при необходимости создаёт локальный репозиторий. GitHub-репозиторий должен существовать заранее.

Утилита не выполняет force push, не переписывает историю, не завершает merge/rebase и не удаляет блокировки Git. Подготовленные вручную изменения в каталоге экспорта нужно сначала сохранить или убрать из индекса. При отказе GitHub локальный коммит остаётся на диске.

## Автоматический запуск

**Сохранить как сценарий** создаёт `.ps1` и отдельный зашифрованный `.settings.dat` со снимком параметров и флажков. Последующие изменения в GUI не меняют этот снимок.

Пример аргументов для `powershell.exe` в Планировщике Windows:

```powershell
-NoProfile -ExecutionPolicy RemoteSigned -File "C:\Automation\Export-1C.ps1"
```

Сценарий запускается на том же компьютере под тем же пользователем Windows, который его создал. Для переноса на другой сервер настройте утилиту и создайте сценарий на нём. Сценарий сам не добавляет задачу в Планировщик.

По умолчанию тайм-аут всей очереди — 180 минут; можно передать `-TimeoutMinutes 240`. Рядом создаётся `.result.json`. Основные коды: `0` — успех, `1` — ошибка записи очереди, `2` — ошибка запуска/настроек, `124` — тайм-аут оболочки. Проверяйте состояние и время отчёта.

## Сборка из исходников

Дополнительные NuGet-пакеты и .NET SDK не требуются. Используется компилятор C# из установленного .NET Framework.

```powershell
git clone https://github.com/Ipslor/OneEsConfigExporter.git
Set-Location OneEsConfigExporter
.\build.ps1
```

Результат: `dist\OneCConfigExporter.exe`, README и инструкция. Если политика PowerShell блокирует скрипт, следуйте политике своей организации; не отключайте её глобально ради сборки.

## Тесты

```powershell
.\test.ps1 -GitPath "C:\Program Files\Git\cmd\git.exe"
```

Набор из девяти проверок использует фиктивную 1С, тестовый медленный Git и отдельные локальные репозитории. Реальные базы и отправка на GitHub не используются. Для DPAPI нужен загруженный профиль текущего пользователя Windows. Артефакты остаются в `tests\artifacts\` и не входят в Git.

GitHub Actions выполняет сборку и этот набор на Windows. Локальные тесты v.2.5 пройдены; реальная платформа и все варианты серверов/лицензирования тестами не эмулируются.

## Безопасность и ограничения

- `settings.dat` содержит реквизиты, хотя зашифрован DPAPI. Не публикуйте его, снимки сценариев и собственные журналы.
- DPAPI привязывает данные к пользователю/компьютеру, но не защищает от программ того же пользователя, администраторов и дампов памяти.
- Пароли 1С передаются платформе в аргументах процесса. Известные секреты маскируются в отображаемых командах и журналах.
- Доверяйте выбранным EXE и локальным Git-хукам/фильтрам. Утилита не является файловой песочницей.
- Сбой экспорта может оставить частичный каталог. Проверка основных XML не является полной проверкой восстановимости конфигурации.
- Прогресс отображает завершённые этапы, а не процент выгруженных байтов.
- Старые версии, ручные команды 1С/Git и сторонние программы не обязаны учитывать блокировку утилиты.

Результаты ревью и оставшиеся ограничения: [CodeReview.md](CodeReview.md). История версии: [CHANGELOG.md](CHANGELOG.md).
